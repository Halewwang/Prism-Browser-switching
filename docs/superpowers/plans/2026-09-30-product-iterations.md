# Prism 产品迭代实施计划

> 使用子代理处理职责独立的工作流；每阶段先检查需求符合性，再检查实现质量。主代理负责集成和最终验证。

**目标：**按已确认的产品评估顺序改善公开测试版交付、来源规则、Profile、规则编辑、路由解释和浏览器管理。

**架构：**保留 PrismCore 规则/队列和 SwiftUI 原生界面。浏览器 Profile 作为可持久化目标扩展，旧应用目标兼容；可见设置作为浏览器偏好保存。来源状态以真实证据为准，不把单测充当实机验证。

**范围：**Chrome/Edge Chromium Profile 优先；签名公证按用户要求跳过；不发布、不更改系统默认处理器、不重置用户数据。新代码在独立 worktree 中构建为隔离测试应用。

## 阶段 1：公开测试版交付入口

- [x] website：集中原生公测发布信息；下载精确 tag/asset；显示 macOS 15+、Universal、公开测试及手动安装说明。
- [x] website/README：清除旧版本、Electron及正则能力等不一致声明。更新导航/下载和新版实际截图，维持现有视觉。
- [x] 检查远端 tag/asset 存在，构建网站并用浏览器验证桌面与窄屏下载信息。

## 阶段 2：来源支持与可靠性

- [x] 来源规则表单呈现当前验证状态，选择器使用同一保守策略；没有实测证据时明确待验证，不伪造名单。
- [x] 增加真实验收清单和可复现的无敏感数据探针汇总；检查 PID 确认、低置信度、未知、浏览器缺失、FIFO、异常恢复。
- [x] 自动单测与真实点击验收分别记录。无法在本机完成的跨系统/硬件样本列出实际缺口。

## 阶段 3：Chrome/Edge Profile

- [x] 扩展 BrowserDescriptor，新增可选 Chromium Profile（旧 JSON 不含字段时仍可解码）。Profile ID 与应用 ID 不混淆。
- [x] 只读解析各自 Local State 的 profile.info_cache；使用真实存在目录；过滤非法路径；不存在配置时保持应用级目标。
- [x] BrowserLauncher 通过 NSWorkspace 参数传 --profile-directory，保持 URL 与参数分离，禁止 shell 拼接。拒绝失效 Profile，恢复到可选目标。
- [x] 扫描/规则/选择器/历史显示 Profile 名称；先红后绿测试 Profile 发现、迁移、失效、启动参数和原有应用目标。

## 阶段 4：规则编辑与撤销（按最新反馈调整）

- [x] 用户最新要求移除底部“此网站以后这样打开”功能：专用菜单和文案删除，弹窗恢复 425×200；原有规则编辑显示范围和目标。
- [x] 保存后提供撤销，复用规则持久化，失败保留草稿；保留原右键快捷入口。
- [x] 来源快捷操作按证据状态提供说明，不暗示所有 App 已认证。

## 阶段 5：规则预览与历史解释

- [x] 在规则页用 URL 与可选来源预览，复用 RuleEngine，不发起真实导航；显示胜出规则、目标和兜底。
- [x] 历史详情给出实际路由方式/状态与可操作纠正入口；不能确定的来源和网页交接明确说明。
- [x] 域名规则覆盖来源规则、目标不可用、规则禁用等先写行为测试。

## 阶段 6：浏览器管理与状态表达

- [x] 保存隐藏/排序/首选偏好，隐藏不等于移除应用；规则目标保持可解释，隐藏项不进入日常选择器。
- [x] 只有真正错误显示警告；无匹配使用中性提示；补齐中文、辅助标签和可读来源。
- [x] 单测覆盖保存/撤销、筛选、多浏览器布局；CUA 验证方向键和数字快捷键。后续发布验证另运行 XCUITest，结果记录于验收报告；不宣称截图证明无障碍合规。
